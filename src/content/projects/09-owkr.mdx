## 여러 운영자가 함께 쓰는 커뮤니티 도구

OWKR 운영진은 참가 명단을 확인하고 팀을 편성하는 한편, 운영진 선발 시험과 Discord 모집도 관리합니다. 저는 다른 기여자와 함께 Match를 개선하고, 시험 웹·시간을달리는소녀·운영 가이드를 연결하는 작업에 참여했습니다.

핵심은 화면을 늘리는 것보다 **같은 참가자를 정확히 식별하고, 여러 사람이 작업해도 변경과 답안을 잃지 않게 하는 것**이었습니다.

## 참가자 확인부터 팀 편성과 공유까지

이름이 바뀌거나 같은 이름을 쓰는 참가자를 잘못 연결하지 않도록 Discord ID를 기준으로 명단과 유저 시트를 연결했습니다. 신규 참가자와 중복 후보는 운영자가 확인한 뒤 반영하고, 표시 이름이 없어도 기존 정보는 유지합니다.

운영자는 명단을 함께 편집하거나 확정한 팀 결과만 전달할 수 있습니다. 공유 데이터에는 참가자 식별자와 팀 위치를 저장하고, 불러올 때 최신 티어를 다시 읽어 오래된 정보를 복제하지 않도록 했습니다.


## 동시에 편집해도 변경을 잃지 않도록

두 운영자가 같은 명단을 고치면 나중 저장이 먼저 저장한 내용을 덮어쓸 수 있습니다. 공동 편집에 revision을 두고, Redis의 비교와 갱신을 하나의 Lua 연산으로 처리했습니다. 기준 revision이 달라진 저장은 최신 명단과 함께 충돌로 반환합니다.

클라이언트는 아직 보내지 않은 변경을 조회 결과로 덮지 않습니다. 충돌 시에는 최신 명단과 안내를 보여주고, 필요한 수정을 다시 적용하도록 했습니다. 다른 운영자의 접속 상태도 같은 조회 흐름에서 확인할 수 있습니다.

<details class="case-notes">
<summary>공동 편집의 구현과 검증</summary>

공유 세션은 Discord ID·참가 순서·팀 위치를 중심으로 구성하고, 중복 ID와 불완전한 팀 위치를 거부합니다. 화면 동기화는 polling을 사용하며 저장 중인 변경과 조회 응답을 구분하고 숨겨진 탭의 불필요한 조회를 줄였습니다.

저장소 테스트는 revision 증가와 stale 저장의 거절을 확인합니다. Redis 테스트 대역을 사용하는 검사이며, 실제 Redis의 동시 요청 부하 검증과는 구분합니다. 구현은 [공동 편집 PR #10](https://github.com/Overwatch-KR/owkr-balance/pull/10)과 [접속자 표시 PR #17](https://github.com/Overwatch-KR/owkr-balance/pull/17)에 있습니다.

</details>

## 답안 저장부터 제출과 채점까지

응시자는 남은 시간과 저장 상태를 보며 답안을 작성하고, 저장에 실패하면 재시도할 수 있습니다. 제출은 진행 중인 저장을 확인한 뒤 처리하고, 제출 중에는 입력을 잠가 답안이 바뀌지 않도록 했습니다.

운영자는 미응답·검토·미채점 문항으로 이동하고 시험의 정지·재개·시간 연장을 관리합니다. 관리자 편집의 충돌 기준은 수정 시작 시 고정하고, 충돌 후에는 초안을 복원할 수 있게 했습니다. 테스트 응시는 일반 관리 현황에서 분리했습니다.

## 시간을달리는소녀로 모집과 대기실 안내

Discord에서 같은 시각의 내전 두 개를 모집할 수 있도록 모집 메시지별 참가 정보를 나누고, 두 대기실의 예약이 겹치지 않게 했습니다. 생성 중인 내전도 예약에 포함하며 실패나 취소는 자신의 예약만 해제합니다.

모집이 마감 시각까지 완료되지 않거나 원본 공지가 삭제되면 해당 내전을 취소하고 안내를 정리합니다. 전송에 실패한 정리 작업은 재시작 뒤 다시 처리하도록 기록해, 취소된 내전이 남거나 다른 모집에 영향을 주지 않게 했습니다.

## 운영 가이드와 복구 절차까지 연결

내전 규칙과 참가 방법, 봇 안내는 OWKR Docs에 모았습니다. 참가자와 운영자가 같은 안내를 확인하도록 모집·취소 규칙과 실제 도구의 동작을 함께 정리했습니다.

운영 시간 조정, 백업과 재시작이 경합하지 않게 잠금을 공유하고, 백업·로그 보관 기한을 정리 작업에 연결했습니다. 삭제 요청이 들어온 뒤 과거 백업을 복원하는 경우에는 요청을 다시 적용한 후 봇을 연결하도록 절차를 남겼습니다.


<details class="case-notes">
<summary>백업·삭제 요청의 검증 범위</summary>

백업 정리는 미리보기와 실제 적용을 구분하고, 생성 기록이 잘못됐으면 삭제 전에 중단합니다. 링크와 관계없는 파일은 정리 대상으로 따라가지 않습니다.

[삭제·복원 검사 PR #19](https://github.com/Overwatch-KR/owkr-gather-bot/pull/19)와 [실제 백업 점검 PR #20](https://github.com/Overwatch-KR/owkr-gather-bot/pull/20)에 격리 테스트와 운영 점검을 구분해 기록했습니다. 삭제 요청을 자동으로 재적용하는 기능은 없으므로 요청 대장에 따른 수동 절차가 필요합니다.

</details>

## 실제 사용과 맡은 역할

Match는 운영진의 명단 편집·팀 편성·결과 공유에 사용합니다. Exam은 운영진 선발 시험을 위한 웹 도구이고, OWKR Docs는 규정과 이용 안내의 진입점입니다. 시간을달리는소녀는 테스트 서버의 파일럿 단계입니다.

저는 참가자 식별과 공동 편집, 답안 저장·채점, 모집의 예약·취소·복구를 담당했습니다. 사용자에게 보이는 상태와 서버가 저장하는 상태를 맞추고, 작업이 중단된 뒤에도 이어갈 수 있는 흐름을 만드는 데 집중했습니다.

<details class="case-notes">
<summary>사용 범위와 테스트 조건</summary>

봇의 2026-10-28 파일럿 점검은 실참가자 없이 복구와 취소 절차를 확인했습니다. 10번째 참가와 모집 완료 후 이탈은 자동 테스트로 다뤘으며, 실제 10명 참가 환경의 전체 검증은 아닙니다. Exam은 검사용 답안의 저장·제출·채점을 확인한 범위로, 운영 Discord 로그인부터의 전체 흐름과 구분합니다.

</details>
